# Day 2 — TD-005 Required-Auth Middleware

## Context

TD-005: `/v1/agent/*` and `/v1/ai/*` routes are anonymous. Any caller
with `run.invoker` on the Cloud Run service can:
- Fake heartbeats, sessions, alerts for arbitrary deviceId values,
  writing forged data into Firestore, Pub/Sub, BigQuery.
- Burn Vertex AI token budget via `/v1/ai/*` with no attribution.

## Day 2 short-path approach

Per Week 1 plan, wire existing Firebase `createRequiredGuard()` around
these routes. Desktop-agent eventually gets device tokens (Day 4-5
auth-gateway), so for Day 2:

- `/v1/ai/*` requires a Firebase ID token (user identity).
- `/v1/agent/*` requires either a Firebase ID token (owner from
  mobile) or a Google OIDC ID token (desktop-agent / service-to-
  service with audience = our service URL). Unified "authenticated
  caller" middleware, kind = user | service.

Desktop-agent in the repo already runs against ADC / metadata server
on Cloud Run boundary, so adding OIDC-token-passing to its HTTP
client is a small change.
